## 2. 계정과 권한

- **게스트 계정**: 앱을 처음 열면 기기마다 자동 생성됩니다. 기본 닉네임은 `사육자1234` 형식이며 전체 › 프로필 편집에서 바꿀 수 있습니다.
  검색엔진·링크 미리보기·배포 스크린샷 같은 봇(자동화 브라우저)에는 계정을 만들지 않고 브랜드 화면만 보여 줍니다.
- **운영자 권한**: 전체 › 계정 › **관리자 코드 입력**에 운영자 코드를 넣으면 그 기기 계정이 운영자가 됩니다. 운영자는 공지 작성·삭제, 모든 게시글 삭제가 가능합니다.
- 새 관리자 코드가 필요하면 Supabase SQL Editor에서 실행합니다:

  ```sql
  insert into public.invite_codes (code, role, max_uses, expires_at, note)
  values (private.random_code(8), 'admin', 1, now() + interval '30 days', '운영자 추가')
  returning code;
  ```

- 특정 회원 이용 제한: `update public.profiles set status = 'blocked' where nickname = '닉네임';`

## 3. 할 일 알림 · 웹 푸시

1. 회원이 전체 › 설정 › **기기 알림(푸시)** 를 켜면 브라우저 알림 구독이 저장됩니다.
2. Supabase `pg_cron`이 1분마다 알림 시각이 된 할 일을 알림함에 넣습니다.
3. 푸시 대기 알림이 있으면 `push-dispatch` 함수가 브라우저로 보냅니다. 댓글·Q&A 채택·공지·분양 인수 알림도 같은 경로로 갑니다.

- **iPhone**: Safari에서 공유 › **홈 화면에 추가** 후, 홈 화면 앱에서 푸시를 켜야 합니다 (iOS 16.4 이상).
- **Android·PC Chrome/Edge**: 브라우저에서 바로 켤 수 있습니다.
- 발송 상태 확인 (SQL Editor):

  ```sql
  select push_state, count(*) from public.notifications group by 1;
  select * from net._http_response order by created desc limit 10;  -- 최근 함수 호출 결과
  ```

## 4. 나중에 구글 · 카카오 로그인 붙이기

게스트 계정에 소셜 계정을 **연결(link)** 하면 지금까지의 기록이 그대로 유지됩니다.

1. Supabase › Authentication › **Sign In / Providers**
   - Google: Client ID / Secret 입력 후 켜기
   - Kakao: REST API 키 / Client Secret 입력, **Allow users without an email** 켜기 (비즈 앱이 아니면 이메일 동의 항목을 받을 수 없음)
   - **Allow manual linking** 켜기 (게스트 → 소셜 계정 연결에 필요)
2. Supabase › Authentication › **URL Configuration**
   - Site URL: `https://villain-era-app.netlify.app`
   - Redirect URLs: `https://villain-era-app.netlify.app/**`, `http://localhost:5173/**`
3. 각 개발자 콘솔의 리디렉션 URI: `https://pmbalwxxxpgjjdwuvmjv.supabase.co/auth/v1/callback`
4. 앱 코드: 전체 화면에 "구글로 계정 보관하기 / 카카오로 계정 보관하기" 버튼을 추가하고
   `supabase.auth.linkIdentity({ provider: 'google' | 'kakao' })`를 호출합니다.
   다른 기기에서는 `signInWithOAuth`로 같은 계정에 로그인합니다.

## 5. 클로즈드 베타(초대 코드)로 바꾸기

초대 코드 테이블과 `redeem_invite` 함수는 이미 DB에 있습니다.
가입 직후 상태를 `pending`으로 바꾸고(`private.handle_new_user`), 앱에 "초대 코드 입력" 화면을 추가하면 됩니다.

## 6. 용량 · 비용 (무료 플랜 기준)

| 항목 | 한도 | 이 앱의 대응 |
|---|---|---|
| Supabase DB | 500MB | 텍스트 기록 위주라 여유 |
| Supabase Storage | 1GB, 파일당 50MB | 사진은 기기에서 1600px로 줄여 업로드, 동영상 50MB·3분 제한 |

| 활성 프로젝트 | 2개 | 현재 `VILLAIN ERA`(뭄바이) + `villain-era-app`(서울) |
| Netlify 크레딧 (팀 전체) | 월 300 | 운영 배포 1회 15, 전송량 1GB당 20 — 아래 참고 |

무료 플랜 프로젝트는 **7일 이상 요청이 없으면 일시 정지**될 수 있습니다. 정식 오픈 전에는 Pro 플랜 전환을 권장합니다.

### Netlify 크레딧 (2026-10-08 소진 → 다음 결제 주기에 재개)

- 무료 플랜은 팀 전체(검증용 사이트 포함) 월 **300 크레딧**. **운영 배포 1회 = 15 크레딧**, 전송량 1GB = 20 크레딧.
  PR **미리보기 배포·브랜치 배포는 무료**입니다.
- 크레딧을 다 쓰면 사이트는 계속 열리지만 **운영 배포가 멈춥니다**(배포 목록에 'Skipped'). 다음 결제 주기 시작에 다시 채워지며, 그 뒤 `main`에 push하면 자동 배포가 재개됩니다. 정확한 갱신일은 Netlify 팀 › Billing에서 확인할 수 있습니다.
- 절약 규칙
  - 문서(`docs/`, `README.md`, `CLAUDE.md`)·`supabase/`만 바뀐 커밋은 `netlify.toml`의 `ignore` 규칙으로 빌드를 건너뜁니다.
  - 기능 수정은 브랜치 → PR(무료 미리보기로 확인) → 여러 변경을 모아 `main`에 한 번 병합합니다.
- 자주 배포해야 하면 Personal 플랜(월 $9, 1,000 크레딧, 자동 충전 가능)으로 바꾸면 바로 재개됩니다.

## 7. 보안 메모

- GitHub 저장소는 **공개**입니다 (2026-10-08 전환). Netlify 무료 플랜은 비공개 저장소에서 팀원 외 기여자가 있는 커밋(Claude 공동 작성자 표기 포함)의 빌드를 막기 때문입니다. 비밀값은 저장소에 두지 않고 Supabase Vault·Netlify 환경변수에만 둡니다.

- 모든 테이블에 RLS 적용: 사육 데이터는 본인만, 커뮤니티·공지는 회원만 읽기 가능
- 역할·상태·좋아요 수·채택 여부 같은 값은 컬럼 권한으로 클라이언트가 직접 바꿀 수 없음
- 서버 비밀값(푸시 VAPID 키, 함수 호출 비밀값)은 Supabase Vault에만 저장
- 게스트 계정은 누구나 만들 수 있으므로 공개 홍보 전에는 Supabase › Authentication › **Attack Protection**에서 CAPTCHA(Cloudflare Turnstile) 사용을 권장
- 이메일·비밀번호 로그인은 쓰지 않으므로 Supabase › Sign In / Providers › **Email**을 꺼 두면 공격 면이 줄어듭니다 (보안 점검의 'Leaked Password Protection' 경고도 이메일 로그인용)
- 보안 점검의 'Anonymous Access Policies' 경고는 게스트 계정 방식에서 의도된 안내입니다 — 모든 정책은 본인 데이터·회원 공개 범위로 제한됨
- 정식 오픈 전 개인정보 처리방침·이용약관 페이지 준비 필요 (닉네임·사진·게시글을 수집)
