## 2. 계정과 권한

- **게스트 계정**: 환영 화면에서 '시작하기'를 누르면 기기마다 만들어집니다. 기본 닉네임은 `사육자1234` 형식이며 전체 › 프로필 편집에서 바꿀 수 있습니다.
  버튼을 눌러야 계정이 생기므로 검색엔진·링크 미리보기 같은 봇에는 계정이 생기지 않습니다(봇 방문은 집계에서도 빠집니다).
- **다른 기기에서 이어 쓰기**: 전체 › 계정 › 다른 기기에서 이어 쓰기의 8자리 코드로 같은 계정을 다른 기기·홈 화면 앱에서도 씁니다(13절).
- **운영자 권한**: 전체 › 계정 › **관리자 코드 입력**에 운영자 코드를 넣으면 그 계정이 운영자가 됩니다(연결한 기기 모두에 적용). 운영자는 공지 작성·삭제, 모든 게시글 삭제가 가능합니다.
- 새 관리자 코드가 필요하면 Supabase SQL Editor에서 실행합니다:

  ```sql
  insert into public.invite_codes (code, role, max_uses, expires_at, note)
  values (private.random_code(8), 'admin', 1, now() + interval '30 days', '운영자 추가')
  returning code;
  ```

- 특정 회원 이용 제한: `update public.profiles set status = 'blocked' where nickname = '닉네임';`

## 3. 할 일 알림 · 웹 푸시

1. 회원이 전체 › 설정 › **기기 알림(푸시)** 를 켜면 브라우저 알림 구독이 저장됩니다.
2. Supabase `pg_cron`이 1분마다 알림 시각이 된 할 일을 알림함에 넣습니다.
3. 푸시 대기 알림이 있으면 `push-dispatch` 함수가 브라우저로 보냅니다. 댓글·Q&A 채택·공지·분양 인수 알림도 같은 경로로 갑니다.

- **iPhone**: Safari에서 공유 › **홈 화면에 추가** 후, 홈 화면 앱에서 푸시를 켜야 합니다 (iOS 16.4 이상).
- **Android·PC Chrome/Edge**: 브라우저에서 바로 켤 수 있습니다.
- 발송 상태 확인 (SQL Editor):

  ```sql
  select push_state, count(*) from public.notifications group by 1;
  select * from net._http_response order by created desc limit 10;  -- 최근 함수 호출 결과
  ```

## 4. 나중에 구글 · 카카오 로그인 붙이기

게스트 계정에 소셜 계정을 **연결(link)** 하면 지금까지의 기록이 그대로 유지됩니다.

1. Supabase › Authentication › **Sign In / Providers**
   - Google: Client ID / Secret 입력 후 켜기
   - Kakao: REST API 키 / Client Secret 입력, **Allow users without an email** 켜기 (비즈 앱이 아니면 이메일 동의 항목을 받을 수 없음)
   - **Allow manual linking** 켜기 (게스트 → 소셜 계정 연결에 필요)
2. Supabase › Authentication › **URL Configuration**
   - Site URL: `https://villain-era-app.netlify.app`
   - Redirect URLs: `https://villain-era-app.netlify.app/**`, `http://localhost:5173/**`
3. 각 개발자 콘솔의 리디렉션 URI: `https://pmbalwxxxpgjjdwuvmjv.supabase.co/auth/v1/callback`
4. 앱 코드: 전체 화면에 "구글로 계정 보관하기 / 카카오로 계정 보관하기" 버튼을 추가하고
   `supabase.auth.linkIdentity({ provider: 'google' | 'kakao' })`를 호출합니다.
   다른 기기에서는 `signInWithOAuth`로 같은 계정에 로그인합니다.

## 6. 용량 · 비용 (무료 플랜 기준)

| 항목 | 한도 | 이 앱의 대응 |
|---|---|---|
| Supabase DB | 500MB | 텍스트 기록 위주라 여유 |
| Supabase Storage | 1GB, 파일당 50MB | 사진은 기기에서 1600px로 줄여 업로드, 동영상 50MB·3분 제한 |
| Edge Function 호출 | 월 50만 회 | 푸시 대기 알림이 있을 때만 호출 |
| 활성 프로젝트 | 2개 | 현재 `VILLAIN ERA`(뭄바이) + `villain-era-app`(서울) |
| Netlify 크레딧 (팀 전체) | 월 300 | 운영 배포 1회 15, 전송량 1GB당 20 — 아래 참고 |

무료 플랜 프로젝트는 **7일 이상 요청이 없으면 일시 정지**될 수 있습니다. 정식 오픈 전에는 Pro 플랜 전환을 권장합니다.

### Netlify 크레딧 (2026-10-08 소진 → 다음 결제 주기에 재개)

- 무료 플랜은 팀 전체(검증용 사이트 포함) 월 **300 크레딧**. **운영 배포 1회 = 15 크레딧**, 전송량 1GB = 20 크레딧.
  PR **미리보기 배포·브랜치 배포는 무료**입니다.
- 크레딧을 다 쓰면 사이트는 계속 열리지만 **운영 배포가 멈춥니다**(배포 목록에 'Skipped'). 다음 결제 주기 시작에 다시 채워지며, 그 뒤 `main`에 push하면 자동 배포가 재개됩니다. 정확한 갱신일은 Netlify 팀 › Billing에서 확인할 수 있습니다.
- 절약 규칙
  - 문서(`docs/`, `README.md`, `CLAUDE.md`)·`supabase/`만 바뀐 커밋은 `netlify.toml`의 `ignore` 규칙으로 빌드를 건너뜁니다.
  - 기능 수정은 브랜치 → PR(무료 미리보기로 확인) → 여러 변경을 모아 `main`에 한 번 병합합니다.
- 자주 배포해야 하면 Personal 플랜(월 $9, 1,000 크레딧, 자동 충전 가능)으로 바꾸면 바로 재개됩니다.

## 7. 보안 메모

- GitHub 저장소는 **공개**입니다 (2026-10-08 전환). Netlify 무료 플랜은 비공개 저장소에서 팀원 외 기여자가 있는 커밋(Claude 공동 작성자 표기 포함)의 빌드를 막기 때문입니다. 비밀값은 저장소에 두지 않고 Supabase Vault·Netlify 환경변수에만 둡니다.

- 모든 테이블에 RLS 적용: 사육 데이터는 본인만, 커뮤니티·공지는 회원만 읽기 가능
- 역할·상태·좋아요 수·채택 여부 같은 값은 컬럼 권한으로 클라이언트가 직접 바꿀 수 없음
- 서버 비밀값(푸시 VAPID 키, 함수 호출 비밀값)은 Supabase Vault에만 저장
- 게스트 계정은 누구나 만들 수 있으므로 공개 홍보 전에는 Supabase › Authentication › **Attack Protection**에서 CAPTCHA(Cloudflare Turnstile) 사용을 권장
- Supabase › Sign In / Providers › **Email은 켜 둡니다** — 다른 기기에서 이어 쓰기(13절)가 이메일 방식의 일회용 로그인 열쇠를 씁니다. 끄면 기기 연결이 멈춥니다. 보안 점검의 'Leaked Password Protection' 경고는 비밀번호 로그인용이라 이 앱과 관계없습니다.
- 보안 점검의 'Anonymous Access Policies' 경고는 게스트 계정 방식에서 의도된 안내입니다 — 모든 정책은 본인 데이터·회원 공개 범위로 제한됨
- 정식 오픈 전 개인정보 처리방침·이용약관 페이지 준비 필요 (닉네임·사진·게시글을 수집)

## 9. 신고 처리 · 금칙어

- 가입한 지 하루가 지난 서로 다른 회원 3명이 신고한 글·댓글은 자동으로 숨겨집니다(작성자·운영자에게는 '숨김'으로 보임).
  게스트 계정은 버튼 한 번으로 만들어지므로, 새 계정 여러 개로 남의 글을 숨기는 악용을 막으려고 가입 하루 미만 계정의 신고는 인원에 세지 않습니다(신고 기록과 운영자 알림은 그대로).
- 운영자에게는 신고가 들어올 때 알림이 가고, **검증 현황 › 신고** 탭에서 숨김·숨김 해제·삭제·기각·회원 이용 제한을 처리합니다. 운영정책에 '24시간 안 확인'을 약속했습니다.
- 채팅 대화 신고는 같은 탭에 '대화'로 들어옵니다. 처리 방법은 17절을 봅니다.
- 금칙어 추가·삭제 (SQL Editor):

  ```sql
  insert into public.banned_words (word) values ('추가할말');
  delete from public.banned_words where word = '지울말';
  ```

## 13. 다른 기기에서 이어 쓰기 (연결 코드 · 2026-11-19, 0.9.1-beta)

- **쓰던 기기**: 전체 › 계정 › **다른 기기에서 이어 쓰기** → 8자리 코드(10분 동안 한 번만). **새 기기**: 처음 화면 › **이미 쓰던 기록이 있어요** → 코드 입력 → 같은 계정으로 들어가고, 두 기기 모두 계속 씁니다.
- 아이폰 사파리에서 기록이 생기면 홈 위에 '홈 화면 앱으로 옮기기' 3단계 안내와 [코드 받기]가 나옵니다. 아이폰 홈 화면 앱의 처음 화면에는 "사파리에서 쓰던 기록이 있나요?"가 보입니다.
- 이미 빈 계정을 만든 기기는 같은 시트의 **다른 기기의 기록을 이 기기로 불러오기**로 전환합니다(빈 계정은 지워짐). 개체·글·댓글·할 일이 있거나 운영자인 계정은 실수로 기록을 잃지 않도록 전환하지 않습니다.
- **다른 기기 모두 연결 끊기**: 이 기기를 뺀 로그인을 모두 끊습니다. 다른 기기는 최대 1시간 안에 처음 화면으로 돌아갑니다(코드가 남에게 새었을 때).
- 동작: Edge Function `device-link`(create·redeem·revoke, `verify_jwt` 끔 — 함수 안에서 토큰을 확인). 처음 코드를 만들 때 계정에 메일을 받을 수 없는 내부 주소 `<계정ID>@device.villain-era.invalid`를 '확인됨'으로 붙이고(이때 계정의 익명 표시가 풀림), 코드를 쓰면 관리자 링크 생성으로 일회용 열쇠를 만들어 새 기기가 `verifyOtp`로 로그인합니다. **메일은 발송되지 않습니다.**
- 데이터: `private.device_link_codes`(코드는 SHA-256 해시만), `private.device_link_attempts`(IP 해시, 시도 제한). 같은 IP에서 10분에 실패 10번이면 잠시 잠기고, 같은 계정의 코드 만들기는 10분에 5번까지. 하루 지난 행은 함수가 지웁니다.
- **지켜야 할 설정**
  - Authentication › Sign In / Providers › **Email은 켜 둡니다**(끄면 연결이 멈춤).
  - Authentication › Emails › **보안 알림 메일(이메일 변경 알림 등)을 켜지 않습니다** — 내부 주소로 메일이 나가 반송되면 Supabase 메일 발송이 제한될 수 있습니다.
- 사용 수 확인 (SQL Editor):

  ```sql
  select day, count(*) from public.usage_events where name = 'device_link' group by 1 order by 1 desc;
  select count(*) as linked_accounts from auth.users where email like '%@device.villain-era.invalid';
  ```

- 계정이 지워졌거나 연결이 끊긴 기기는 '앱을 시작하지 못했어요' 대신 처음 화면으로 돌아가고, "이 기기의 계정 연결이 끊어져 처음 화면으로 돌아왔어요" 안내가 한 번 보입니다. 인터넷이 실제로 끊긴 경우에만 '다시 시도' 화면이 나옵니다.

## 15. 제품 QR 시작 화면

- 와구와구 제품의 포장이나 동봉 카드에 넣는 QR입니다. 주소는 `https://villain-era-app.netlify.app/p/<제품>?src=pack-<제품>` 형식입니다(예: `/p/signature?src=pack-signature`).
- 계정이 없는 기기에서 열면 환영 화면에 제품 카드가 보이고, '시작하고 급여 기록하기'를 누르면 그 사료를 **내 사료**로 기억한 뒤 개체 등록 → 급여 기록으로 이어집니다. 이미 쓰는 기기에서 열면 제품 화면의 '이 사료로 급여 기록하기'가 한꺼번에 급여 기록으로 보냅니다.
- **내 사료**는 그 기기의 브라우저에만 저장됩니다(`localStorage`의 `ve-food`). 급여 기록에서 그 개체가 먹던 먹이가 없을 때 기본 먹이가 되고, 먹이 칩의 맨 앞에 나옵니다. 크레스티드게코·리키에너스의 먹이 칩에는 QR을 찍지 않아도 와구와구 제품이 들어 있습니다.
- `pack-<제품>`으로 들어와 시작한 사람 수는 검증 현황의 유입 경로별 표에 따로 잡힙니다.
- **제품 내용 바꾸기**: `src/lib/products.ts`의 표를 고칩니다. 문구는 표기사항(`표기사항/후면 표기사항 v2.pdf`, 시제품)을 그대로 옮긴 것이라, 판매용 표기사항이 확정되면 다시 맞춥니다. 급여 방법(`guide`)은 문구가 확정되지 않아 비어 있고, 비어 있으면 화면에 그 칸이 나오지 않습니다. 효능(질병 예방·치료, 성장) 표현은 넣지 않습니다.
- **QR 다시 만들기**: 제품을 더하면 `scripts/make-product-qr.mjs`의 목록에도 더하고 아래를 실행합니다. 파일은 저장소 밖 설계 폴더의 `제품 QR/`에 생깁니다.

  ```bash
  node scripts/make-product-qr.mjs
  ```

- **아이폰의 한계**: QR은 사파리에서 열리는데, 홈 화면 앱은 사파리와 저장소가 따로라 홈 화면 앱의 계정으로 이어지지 않습니다. 홈 화면 앱을 쓰는 사람은 급여 기록의 먹이 칩에서 제품을 직접 고르면 됩니다.

## 16. 분양·홍보 게시판과 분양 이력서

- **분류**: 커뮤니티에 '분양·홍보'가 있습니다. 글을 쓸 때 글 종류(분양·홍보), 개체, 희망 분양가, 지역, 판매자 구분(개인·사업자)을 고르고 법 안내를 확인합니다. 글의 분양 카드는 서버가 다시 만들기 때문에(트리거 `posts_adopt`), 화면을 거치지 않고 보낸 값이나 남의 개체는 붙지 않습니다.
- **새 계정 제한**: 프로필을 만든 지 24시간이 지나고 개체가 1마리 이상인 계정만 분양·홍보 글을 쓸 수 있습니다(`private.can_trade`, 운영자는 예외). 기준을 바꾸려면 이 함수와 `src/lib/adopt.ts`의 `TRADE_MIN_HOURS`를 함께 고칩니다.
- **분양 상태**: 분양 글은 '분양 중'으로 시작하고, 글쓴이나 운영자가 글 화면에서 '예약 중'·'분양 완료'로 바꿉니다(`set_adopt_status`).
- **분양 이력서**: 개체 상세 › 분양 이력서에서 링크(`/r/<토큰>`)를 만들고 끕니다. 계정 없이 열리며 개체 정보·사진, 체중(최근 200회), 최근 90일 급여(먹이 이름), 부모, 분양자 닉네임을 보여 줍니다. 건강 기록·급여량·메모는 넣지 않습니다. 이용이 제한된 계정의 이력서는 보이지 않습니다.
  - 살아 있는 링크 수: `select count(*) from public.animal_shares where revoked_at is null;`
- **분양 이전과의 차이**: 이력서는 분양 전에 보여 주기만 하고 개체 상태를 바꾸지 않습니다. 분양 이전(기존 기능)은 받는 사람 계정으로 기록을 복사하고 개체를 '분양' 상태로 바꿉니다.
- **신고 처리**: 분양·홍보 글도 기존 신고(서로 다른 3명이면 자동 숨김)와 운영자 처리(9절)를 그대로 씁니다. 불법 거래로 보이는 글은 신고 사유 '불법'으로 들어옵니다.
- **법 안내 문구**: `src/lib/adopt.ts`의 `LAW_NOTES`·`NOT_A_PARTY`·`WIMS_URL` 한 곳에 있고, 글쓰기·글·이력서·운영정책이 함께 씁니다. 출처는 원주시 공지(2026-03-06)와 고양시 보도자료(2026-01-07)입니다. 기준이 바뀌면 여기만 고칩니다.
- **운영에 열기 전에 확인할 것** (설계서 6절): VILLAIN ERA가 통신판매중개에 해당하는지와 그에 따른 운영자 표시(사업자등록번호 등), 가고일게코·리키에너스의 백색목록 포함 여부, 야생동물 택배 규정. 병합할 때는 `src/lib/operator.ts`의 시행일을 바꾸고 앱 공지로 약관·처리방침·운영정책 변경을 알립니다.
- DB: 마이그레이션 `20261127000001_adopt_board.sql`, 시험 `supabase/tests/adopt_board.sql`.

## 17. 채팅과 운영자 문의

- **1:1 채팅**: 하단 탭 '채팅'. 분양·홍보 글의 '채팅으로 문의'나 글·댓글의 ⋯ 메뉴 › 채팅 보내기로 시작합니다. 같은 두 사람의 대화방은 하나이고, 글에서 열면 그 글이 대화 위에 붙습니다(다른 글에서 다시 열면 그 글로 바뀜).
- **제한**: 새 대화는 분양·홍보 글과 같은 조건(`private.can_trade`: 24시간 + 개체 1마리, 운영자 예외)이고 24시간에 10개까지입니다. 메시지는 글자만 1000자, 한 사람이 1분에 20개까지입니다. 받은 메시지에 답하는 것은 조건 없이 됩니다. 숫자를 바꾸려면 `open_dm`·`send_message`와 `src/lib/chat.ts`의 `CHAT_DAILY_NEW`·`CHAT_MAX`를 함께 고칩니다.
- **메시지는 함수로만** 들어갑니다(`send_message`). 표에 직접 쓸 수 없고, 참여자 확인·차단·금칙어·속도 제한·알림을 이 함수가 처리합니다. 알림은 같은 방에 10분에 한 번이고 메시지 내용은 넣지 않습니다.
- **차단**: 어느 한쪽이라도 차단하면 서로 보낼 수 없습니다. 차단한 사람에게는 그 방이 보이지 않고, 차단당한 사람에게는 방이 남아 있지만 보내면 '이 대화에는 메시지를 보낼 수 없어요'가 나옵니다.
- **운영자 문의**: 전체 › 도움말·문의(`/inquiry`). 회원마다 운영자와의 대화방이 하나 있고 시작 조건이 없습니다. 문의가 오면 운영자 계정에 알림이 가고, **검증 현황 › 문의** 탭에서 읽고 답합니다(답하지 않은 문의 수가 탭에 보임). 운영자가 여러 명이면 누구나 답할 수 있습니다.
- **대화 신고**: 대화 화면의 메뉴 › 대화 신고. **검증 현황 › 신고**에 '대화'로 들어오고 '대화 보기'로 내용을 읽습니다. 운영 화면에서는 **신고가 열려 있는 동안만** 그 대화를 읽을 수 있고, 기각하거나 회원 이용 제한으로 처리하면 다시 볼 수 없습니다. 대화 신고에는 숨김·삭제가 없습니다.
- **운영자가 지킬 것**: 처리방침에 '신고 처리와 법령에 따른 요청 말고는 채팅 내용을 열어 보지 않는다'고 적었습니다. SQL Editor로 `chat_messages`를 들여다보지 않습니다.
- **계정 삭제**: 한 사람이 계정을 지우면 그 사람이 참여한 대화방과 메시지가 함께 지워져 상대방 화면에서도 사라집니다. 분쟁에 대비해 일정 기간 남겨 두려면 처리방침의 보유 기간과 함께 바꿔야 합니다(설계서 6절의 확인할 것 5번).
- **실시간**: 열려 있는 대화는 Supabase Realtime으로 새 메시지를 바로 받습니다(무료 플랜 동시 접속 200). 연결이 막힌 환경을 대비해 20초마다 다시 읽고, 대화 목록과 안 읽은 수는 30초마다 다시 읽습니다.
- 살펴보기:

  ```sql
  -- 대화방 수와 최근 7일 메시지 수 (내용은 보지 않는다)
  select kind, count(*) from public.chat_rooms group by kind;
  select count(*) from public.chat_messages where created_at > now() - interval '7 days';
  ```

- DB: 마이그레이션 `20261127000002_chat.sql`, 시험 `supabase/tests/chat.sql`.
